Agent 開始審查 Agent 前，我先用 ccusage 審查了自己

我是怎麼發現 ccusage？#

事情是這樣的，我目前用 Gemini 和 Google Workspace Studio 做定期推播，提供每日 Todo 結合金融新聞重點摘要服務，但近期的 Todo 常常抓不到，而且美股盤後資訊或新聞資訊有時候會給錯（幻覺）！有時候要他給我數值，它變成「大跌」、「大漲」這種敘述。讓我覺得你怎麼又自我發揮。於是想到，或許能參考網路上很流行的龍蝦（OpenClaw）架構，讓 Agent 審查 Agent。

但是，龍蝦這種模式很燒 Token，容易把我們錢用完，所以要謹慎使用。但我不知道自己平常用多少 Token、每個 session 消耗多少。像是在自己的電腦中，平常在使用 Claude 方案時（如 Pro/Team）不用管 Token 花費，但當開始在終端機（CLI）串接 API 寫 Agent 或開發時，是按 Token 計費的（用多少算多少），如果不注意很容易把餘額燒光。網頁版（或是桌面版）通常只看得到百分比的使用限制，我很難知道自己真實用了多少 Token、花了多少錢，自己有沒有過度浪費 Token 的問題？

於是我找到了一個好用工具－ ccusage ，它就像是 AI 時代的「電子記帳本」，專門幫忙統計透過 CLI 呼叫各家大模型的 Token 消耗與真實美金花費。

🛠️ 同場加映：ccusage 簡單上手指南#

ccusage 其實非常好懂。當在終端機（CLI）頻繁呼叫 AI 模型（使用網頁版就無效）後，只要輸入簡單的指令，它就會掃描你電腦中的紀錄並產出報表。

常用指令#

直接在終端機輸入 ccusage daily（看每日用量）或 ccusage monthly（看每月總結）。

報表看什麼#

  • Input / Output：你餵給 AI 的字數（Prompt + 檔案）與 AI 回答的字數。
  • Cache Create / Read：這是省錢關鍵！現在很多模型支援「提示詞快取」，把大專案丟給 AI 第一次會算 Create，之後對話都是 Read，費用極低。
  • Cost (USD)：直接幫你把 Token 結合使用的模型，換算成美金花費。

注意 Desktop 版本 是不同東西#

在 Claude 的 Desktop 版本跟網頁版相同，不會在本機記錄，只有調用 API 時候會。以我的案例就是用在 VS Code 或是用 CLI 模式才會統計。

所以在用的時候要注意，如果都想要統計到，就要用「終端機」模式。

記帳本大解析：我的 2.89 億「快取」驚奇之旅#

打開我自己的 ccusage daily 報表，總結下來我這陣子的總花費是 $266.13 美金。經過詳細的數據解析，我發現了自己的幾個重度使用特徵：

我是快取浪費大師#

我的 Cache Read（讀取快取） 累積高達 289,574,518 tokens（約 2.89 億）！這意味著我在開發過程中，大量重複使用了幾十萬字的大型專案上下文。如果沒有妥善利用 Prompt Caching 機制，每次對話都重新計算 Input，我的帳單絕對會翻好幾倍。

（仔細觀察後，是夾帶一堆檔案進行作業，但是沒有善加利用其他技巧，導致不斷的讀取資料。）

雙引擎的 M 型化#

我主要混用 Gemini 與 Claude，但它們在帳單上呈現完全不同的風景：

  • 日常平價勞工（Gemini CLI）：像是 gemini-2.5-pro 或 3.1-pro-preview，雖然處理了幾十萬 tokens，但單日花費極低，多半在 $0.10 到 $1.70 美金之間徘徊。
  • 重裝燒錢武器（Claude Opus）：在近兩個月的密集開發期，我大量徵召了 opus-4-7 與 opus-4-8。智商極高，但成本驚人，單日花費經常突破 $30 甚至高達 $44.29 美金。佔據了我 95% 以上的總開銷！

這表示我沒有善加利用他們，沒有適時的切或模組，或是妥善的分工，導致讓 Claude 被過度使用。

從「看帳單」到「造大腦」：我的 Agent 工作流構想#

回到為了解決這個坑，也為了不讓昂貴的 Token 繼續打水漂，我設計了以下的「防呆架構」：

  • 拒絕依賴 AI 記憶，改用「硬動作」抓 Todo： 抓不到近期任務，是因為太依賴 AI 的對話快取。工作流的第一步必須設定一個強制的 API Call，直接去 Google Tasks 或 Notion 撈取 今天最新 的未完成清單，轉成純文字後再餵給 AI 進行排程。
  • 引入「事實查核員」的雙 Agent 機制： 美股盤後數字出錯絕對不能忍。因此不能只用一個 Prompt，必須建立雙代理（Multi-Agent）對抗架構：
    • Agent A（撰稿員）：負責上網抓美股新聞、寫出簡報草稿。
    • Agent B（校對員）：唯一任務就是「找碴」。把草稿裡的股價、漲跌幅數字，拿去跟權威財經 API 的真實數據逐一比對，有錯立刻強制覆寫！

在乎 Token，才是 AI 建造者的起點#

這次從 ccusage 檢視帳單出發，開始在意 Token 之後，思考方式也跟以前不太一樣了。過去我只是想把問題丟給 AI 解決，現在則會開始思考怎麼讓它更便宜、更準、更穩定。

接下來我打算開始這樣改良，把這些優化邏輯實際落地，讓我的每日早報不再出現這種明顯的錯誤：

目前無法從您的 Google Workspace 資料中存取任何行事曆事件或電子郵件，因此無法為您生成代辦事項。

或是

費城半導體指數：無即時數據提供。

也藉由這種小小工具，讓我成為展現 Agentic workflow 的第一步。
