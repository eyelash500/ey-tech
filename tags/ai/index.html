Agent 開始審查 Agent 前，我先用 ccusage 審查了自己

我是怎麼發現 ccusage？ 事情是這樣的，我目前用 Gemini 和 Google Workspace Studio 做定期推播，提供每日 Todo 結合金融新聞重點摘要服務，但近期的 Todo 常常抓不到，而且美股盤後資訊或新聞資訊有時候會給錯（幻覺）！有時候要他給我數值，它變成「大跌」、「大漲」這種敘述。讓我覺得你怎麼又自我發揮。於是想到，或許能參考網路上很流行的龍蝦（OpenClaw）架構，讓 Agent 審查 Agent。 但是，龍蝦這種模式很燒 Token，容易把我們錢用完，所以要謹慎使用。但我不知道自己平常用多少 Token、每個 session 消耗多少。像是在自己的電腦中，平常在使用 Claude 方案時（如 Pro/Team）不用管 Token 花費，但當開始在終端機（CLI）串接 API 寫 Agent 或開發時，是按 Token 計費的（用多少算多少），如果不注意很容易把餘額燒光。網頁版（或是桌面版）通常只看得到百分比的使用限制，我很難知道自己真實用了多少 Token、花了多少錢，自己有沒有過度浪費 Token 的問題？ 於是我找到了一個好用工具－ ccusage ，它就像是 AI 時代的「電子記帳本」，專門幫忙統計透過 CLI 呼叫各家大模型的 Token 消耗與真實美金花費。 🛠️ 同場加映：ccusage 簡單上手指南 ccusage 其實非常好懂。當在終端機（CLI）頻繁呼叫 AI 模型（使用網頁版就無效）後，只要輸入簡單的指令，它就會掃描你電腦中的紀錄並產出報表。 常用指令 直接在終端機輸入 ccusage daily（看每日用量）或 ccusage monthly（看每月總結）。 報表看什麼 Input / Output：你餵給 AI 的字數（Prompt + 檔案）與 AI 回答的字數。 Cache Create / Read：這是省錢關鍵！現在很多模型支援「提示詞快取」，把大專案丟給 AI 第一次會算 Create，之後對話都是 Read，費用極低。 Cost (USD)：直接幫你把 Token 結合使用的模型，換算成美金花費。 注意 Desktop 版本 是不同東西 在 Claude 的 Desktop 版本跟網頁版相同，不會在本機記錄，只有調用 API 時候會。以我的案例就是用在 VS Code 或是用 CLI 模式才會統計。 ...

不懂夏威夷？用 Vibe Coding 請 AI 建一個專屬旅遊網

年初做了一個有趣的 Vibe Coding 小專案，起因很蠢——我突然很想去夏威夷，但完全不知道夏威夷有什麼。 因為不瞭解，所以建立了一個網頁去學習 某天看新聞的時候，想到如果今年出國玩也不錯耶。但要去哪裡呢？那就去朝聖某個死神學開直升機的夏威夷。 不過…問題是…我對夏威夷完全不熟，只知道是美國的一部分，但又跟美國本土文化很不一樣。這樣的地方到底有什麼風土民情？到底可以去哪裡觀光？重要的是，要花多少錢呢？ 於是有這些問題，我就用 Vibe Coding 請 Gemini 幫我建立一個網站：2026 夏威夷阿囉哈冒險計畫，來解決我眾多的問題。 一開始我對於夏威夷很不熟悉，因此身為社畜的我，按照基本原則，既然要去，就要去得有意義又省錢，那就去旅遊的時候也參加他們的節日慶典吧！不只逛逛市集，也體驗一下他們的文化。因此我在網站賦予了觀光兼節日的屬性。 接著想到，社畜不能請太多假，會招來白眼，因此要求 AI 幫忙制定一個合理的天數以及旅遊預算，這樣我就可以知道要請多少天的假、準備多少的錢。甚至請 AI 幫我做出省錢計畫，避免我從夏威夷飛回來後要開始吃土。 媲美旅行社的網站與計畫，被現實擊敗 最後完成的 冒險計畫網站，花費我不到半天的時間，就做出可媲美旅行社網站（甚至覺得比很多旅行社厲害），儘管行程和規劃沒有他們那麼專業，但對於完全不知道夏威夷觀光的我，這就是個很好理解及協助規劃的網站。從這邊，我可以快速認識夏威夷一整年著名的節慶與活動，值得探訪的景點，甚至挖出不少原本不會發現的體驗行程。不只讓我對於夏威夷旅遊更嚮往，也使我對於旅行的成本更有概念。最重要的是，不用像以前一樣到處翻旅遊部落格、旅行社行程表，再自己整理成企劃書，全部由 Vibe Coding 就可以做出具有互動性，且資料（還算）齊全的網站，讓資訊收集與行程規劃變得一目了然。 但是計畫來不及變化，今年的我，沒有這麼大筆錢可以飛出去了…Q口Q 不過如果明年有機會，我就可以用 AI 把這個 2026 年計畫改良成更厲害的「2027 年夏威夷計畫」！至於能不能真的飛出去，就不是 Gemini 能解決的問題了。

AI 不是來搶飯碗，讓自己從「養馬人」到「開車者」

近期在公司的 AI 聚會中，不時會聽到大家對於應用 AI 技術的興奮與期待。然而，擁抱新科技同時，面對 AI 的強勢崛起，大家不免在會議中提問到：我們到底該如何善用它？而我們未來的職涯又將會變成什麼模樣？ AI 時代的衝擊與省思 剛開始接觸 AI 的時候，我覺得它就像個很聰明的實習生，你問一句它答一句，不推就不會動。但隨著這兩年技術爆發，今年初我開始將注意力放在 AI Agent，投入了大量時間學習如何使用它。實作一陣子後，深深覺得其能力令人驚艷，現在 AI 帶來的生產力提升，我真的能實現傳聞中「10 倍工程師」的效益（雖然我目前連一半都還沒達到）！ 然而，越是深入研究，越是感到迷惘：我的存在價值會不會就此被 AI 取代？雖然目前臺灣的軟體界還未受到強烈衝擊，畢竟就現實面的成本考量而言： 矽谷軟體工程師 > AI Token > 臺灣軟體工程師 但在國外，許多人已選擇離開受到 AI 浪潮衝擊劇烈的美國，回到臺灣發展。這波由 AI 引起的產業結構改變與裁員潮，也讓我開始警惕。如果等到衝擊真正襲來才開始尋求轉型，恐怕為時已晚。 因此，這段時間除了持續學習 AI 技術外，我也開始廣泛閱讀，試圖了解軟體工程師（或是稱「人」）在 AI 時代的生存之道。在這個過程中，我接觸到了「HITL (Human-in-the-loop，人機協作)」的概念。 HITL 的核心精神是在 AI 執行任務的過程中，仍需要人類來檢視、回饋與下達關鍵判斷。講白一點，HITL 就是 AI 幫你做事，但最後背鍋的人還是你，畢竟晚上被吵醒會生氣的不是 AI，是我們自己。所以與其抗拒，不如把 AI 當成隨傳隨到的助理，結合自己的 domain know-how，把它用好用滿！ 人並未消失，而是轉換了角色與位置 我曾在 AI 聚會中與夥伴們分享過一個比喻：現在我們面對 AI 工具的衝擊，就像是馬車時代的人們遇見了汽車。 在馬車時代，出遠門需要馬伕，旅途中至少要有兩個人與一匹馬。當汽車出現後，我們不再需要馬伕了，自己就能決定目的地。這不僅省去了聘用與溝通成本，旅途時間也變得更加彈性，不再需要遷就馬伕的作息或馬匹的體力。我們只需獨自握住方向盤，就能隨時出發（當時有夥伴打趣地說：現在不都是自動駕駛了嗎XD）。 使用 AI 也是如此，我們可以隨時呼叫 AI 助理群，不用擔心它們是否需要休息或休假，隨時都能上工（自己扮演慣老闆）。 然而在這個過程中，「人」依然是不可或缺的。過去可能需要一個團隊才能完成的任務，現在或許靠自己加上 AI 就能搞定。但關鍵在於，你必須決定方向、規劃路線，這些核心決策是無可取代的。 改變的只是所需的技能門檻：過去我們需要了解馬的習性，現在我們不需要精通汽車的每一個機械結構，就能享受更便利、更高效的移動方式。因此，人類並未在 AI 發展的過程中被淘汰，而是我們的職責與定位進行轉換。 我們不會消失，會成為設計與修車的人 在現代，AI 能協助沒有程式背景的人輕鬆開發出全新的系統。然而，當這些系統需要進行複雜的架構調整或深度改版時，還是會遇到瓶頸。這正是軟體工程師發揮價值的時刻，我們將成為帶領 AI 助理與小工程師們進行系統升級的架構師。 ...

我與 Vibe coding 的第一次相遇，用 Gemini 實踐想像

自從接觸 Gemini 的 Canvas 後，我對於它的強大輸出功能感到驚訝！ 只要給一個小小的藍圖與方向，它就能具現化腦海中的想像，呈現出的視覺美感甚至遠遠超過我的預期（我完全看不到車尾燈）！嚇到吃手手的我，立刻開始研究，到底發生了什麼事情，這到底是什麼神奇的魔法！深入了解後才發現，原來 AI 在 2025 年大躍進，這也催生出一個全新名詞—— Vibe coding（氛圍編碼）。 Vibe coding 實現腦中的想像 當我運用 Vibe coding，輕鬆地打造出想要的「情境」（也就是我想要的氛圍）時，腦中突然閃過一個大膽的念頭：既然如此，我是不是能輕易地將腦中那些複雜的想法與知識，全都化為網頁呢？ 說做就做！我立刻著手製作了 退休金缺口計算機。 Gemini 將「可以退休」這個遙遠的概念，運用視覺化的圖表與實際的數字呈現在我眼前。這使未來的財務藍圖變得具體，讓我對人生規劃有了更踏實的想像。 使用 Vibe coding 打造金融助理團隊 然而這麼強大的 Vibe coding 工具出現後，身邊居然鮮為人知？儘管我用力推廣但是效果有限。後來想到，既然每年都會參加 iThome 的鐵人賽，那不如這次（去年）的鐵人賽就用「Vibe Coding」參賽！於是乎，我開始打造 Gemini 系列教學－30 天打造你的 AI 客戶金融助理團隊。 只是，結果卻出乎意料，我居然在第 24 天斷更了…這次的鐵人賽遺憾地 宣 告 失 敗。 儘管如此，我還是按照計畫，把所有內容發布，藉此完成了一個簡單 AI 助理團隊的建立與學習。 而這，也成為我第一個真正由 AI 協助打造出的專屬團隊。
