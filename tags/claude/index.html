為什麼 AI 總是不聽勸？淺談 Agent 的 Execution Bias (執行偏誤)

前言：差點把我逼瘋的 PRD 前幾天用 Antigravity.app （Gemini model）試圖建立一份 PRD （產品需求文件），整個過程差點把我逼瘋。 我的需求明明很簡單：「先把需求釐清、完成規劃，再開始動工。」結果它三兩句就回我：「好的，需求與架構已釐清，開始建置系統！」接著就眼睜睜看著它直接衝去建資料夾、安裝套件。 我趕緊喊停：「不對，我們還沒確認細節！」它馬上低頭認錯，但沒過 一招，又故態復萌地想跳過規劃直接寫 Code。如此來回拉扯了十幾次，我才像擠牙膏一樣，把 PRD 硬壓出來。 一個被忽略的現象：Execution Bias（執行偏誤） 我後來嘗試整理這種行為模式，發現它其實有一個很清楚的特徵： Antigravity 傾向盡快進入「可執行狀態」，並壓縮規劃階段。 我重新思考這個現象，才理解為什麼會這樣：這不是 Bug，而是系統設計使然。 像 Antigravity 這樣的 AI Agent，它的核心機制與訓練目標就是「寫 Code 與解決問題」，也就是優先產出可執行結果。因此它的底層能力高度集中在操作檔案系統、執行終端機指令、以及修復 Error。對 Antigravity 來說，「產出可執行的程式碼」才叫真正完成任務。 至於寫規劃文件？Antigravity 不是不會寫，只是在它眼裡，那些文字討論都是阻礙它去寫 Code 的「減速丘」。能三句帶過，就絕不囉嗦，因此它只會最低限度地完成你交代的文書任務。這種傾向在 AI 領域有個專有名詞，叫做 「Execution Bias （執行偏誤）」：急著動手，規劃階段越快結束越好。 AI 代理（AI Agent）出現之下，AI 是能調用工具、寫程式碼來執行任務，當它遇到模糊不清的指令時，往往會直接進入執行，甚至一路修正錯誤，陷入無窮無盡的自我修復循環，最後把 token 消耗殆盡。這也是 Execution Bias 常見的副作用。 因此拿 Antigravity 跟純粹的對話模型（如網頁版或官方桌面版的 Claude）相比，它的特性差異就非常明顯了。 Claude 則更像是規劃型角色。你給出一個粗略方向，它會反問關鍵問題，慢慢幫你釐清細節，直到你說：「可以，就照這個方向產出架構文件」，它才會開始輸出最終版本。 一刀切地說：Antigravity 就像是急著動手實作的熱血工程師，而 Claude 則是深思熟慮的系統企劃。 這兩者沒有誰優誰劣，而是適合軟體開發的不同階段。在需求還沒想清楚、架構尚未明朗的時候，如果硬要使用 Execution Bias 強的 Agent 工具，你只會花費成倍的時間在「阻止它寫 code」以及復原它擅自建立的檔案上。 當然，AI 的行為並不是二分法，而是可以透過 Prompt 調整的光譜。 ...

一人團隊的 AI 協作術：如何打造公私分明的 AI 開發工作流

在當今 AI 爆發的時代，身為一個「一人開發團隊」，如何善用各種 AI 工具加速專案開發，同時又能兼顧帳號額度效率與公司智慧財產權 (IP) 安全？ 這篇文章將分享我近期整理出的一套開發工作流，探討如何將 Claude、Antigravity (AI Agent & IDE) 以及 Obsidian 串聯起來，打造出極致且「公私分明」的開發體驗。 一、 釐清概念：AI Agent 與 AI IDE 的區別 許多人在剛接觸這些工具（例如新興的 AI 開發神器 Antigravity）時會感到困惑：「AI 助理（如 Antigravity Agent）和 AI 編輯器（如 Antigravity IDE）有什麼不同？只差在能不能在視窗裡看程式碼嗎？」 其實，兩者的角色定位截然不同： AI Agent（大腦）：它是負責思考與執行的主體。即使你不在特定的 IDE 內，它依然能透過工具讀取你的本機專案、在程式碼中搜尋關鍵字、直接修改檔案，甚至在你的授權下執行本機終端機指令（如 npm install、git push）。 AI IDE（辦公桌）：它是給開發者（你）使用的視覺化介面。它將 Agent 寫好的程式碼即時呈現出來，讓你方便檢視檔案樹、進行語法高亮、手動微調，並提供網頁的即時預覽功能。 二、 多帳號環境下的「公私分明」工具鏈規劃 當我們同時擁有「公司帳號（通常為免費或入門方案）」與「個人帳號（如 Google AI Pro 等高級方案）」時，如果把私人的高級額度拿去跑公司專案，除了很快會把額度耗盡外，也會產生智財權與合規的灰色地帶。 因此，規劃出一套能發揮各家 AI 專長，且帳號界線分明的雙軌開發工具鏈，是現代開發者的必修課： 👤 軌道一：個人開發軌（使用個人 Pro / API 方案） 主力工具： Antigravity CLI/網頁版（綁定個人 Pro 帳號）：享受無限制的額度與強大模型，用來跑自己 Side Project 的專案初始化、程式碼生成與本機測試。 VS Code (搭配個人 API Key)：作為日常寫扣與微調的編輯器。 Obsidian (搭配 Gemini API Key)：作為本地知識庫，整理開發筆記、進行知識萃取與架構發想。 核心目的：最大化個人 Pro 方案價值，專注於個人技術積累與 Side Projects 的敏捷開發。 🏢 軌道二：公司開發軌（使用公司授權/免費額度） 主力工具： Claude Desktop / Claude Code CLI（公司帳號）：負責高層次架構規劃、PRD（產品需求文件）撰寫與主要代碼設計。Claude 極佳的語意邏輯在這邊能發揮最大效益。 Antigravity IDE（公司 Starter 帳號）：只用作輔助性的微調、簡單 Bug 排查，或者根本不使用。 核心目的：確保公司專案的程式碼留在公司授權的管道中。如果未來公司專案非常需要強大的本地 Agent 協作，應向公司申請企業授權，而非使用個人帳號頂替。 三、 給一人團隊的實戰建議 透過上述的工具分工，一人團隊也能展現出極高的戰鬥力： ...
