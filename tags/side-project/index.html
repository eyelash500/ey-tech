當 Antigravity 完成 MVP 後：我的 Side Project 接手實錄

前言 最近，我利用 Antigravity.app 快速地為一個新的 Side Project 想法打造出了一套 MVP (Minimum Viable Product，最小可行性產品)。看著這位我先前在文章中形容為「熱血工程師」的 AI Agent 在短短時間內拔地而起，建立好專案架構、安裝好依賴套件，甚至寫出了初步的功能，整個過程依然令人驚艷。 然而，當 MVP 完成後，真正的挑戰才正要開始。AI 完成了從 0 到 1 的部分，但從 1 到 100 的路，終究需要由我們自己來走。這篇文章將記錄我是如何從 Antigravity 手中「接管」這個專案，並將其一步步塑造成我想要的樣子。 主要內容：接管 AI 的專案 Antigravity.app 產出的專案結構清晰、程式碼也相當標準化，這為後續的開發奠定了良好的基礎。但 AI 的工作成果就像一個剛裝潢好的毛胚屋，雖然格局方正，但缺乏靈魂。我的接手工作主要分為以下幾個階段： 1. 程式碼審查 (Code Review) 與理解 第一步，也是最重要的一步，是徹底讀懂 AI 寫的每一行程式碼。我不會天真地認為 AI 產出的程式碼是完美無缺的。我會像對待一位新同事提交的 Merge Request 一樣，逐一檢視： 架構合理性：AI 選擇的架構是否適合我未來的擴充？例如，它選擇的狀態管理方式是否是我偏好的？如果不適合，現在就是調整的最佳時機。 功能實作完整度：頁面出來後，逐一檢查按鈕、畫面顯示是否有符合我的預期，是否有因沒有文件規範而胡亂作業。 潛在的 Bug：AI 是否有遺漏了哪些邊界情況（Edge Case）？我會手動執行幾次，試圖找出潛在的問題。 2. 注入個人風格與靈魂 在理解了程式碼之後，我開始進行「個人化」的改造。這就像是為毛胚屋添購家具、粉刷牆壁。 重構 (Refactoring)：將部分 AI 寫的邏輯，在快速瀏覽後，用我自己更習慣的設計模式或寫法重構。這不僅是為了統一風格，更是為了確保我對這段程式碼有 100% 的掌控力。 加入註解：在關鍵的業務邏輯或複雜的演算法旁，我會利用 AI 協助加上註解，或是在文件中記錄，讓未來的我或是接手的 AI 可以快速瞭解前因後果，而不會改錯。 建立測試：AI 通常不會幫你寫完整的測試案例。我會開始要求 AI 建立完整的測試架構，像是從需求開始的 TDD（Test-Driven Development，測試驅動開發）、E2E testing（End-to-End testing，端對端測試），或是程式面的單元測試（Unit testing），以確保程式品質的穩定。 3. 規劃下一步 (Roadmap) 當我完全掌握了這個專案雛形後，會建立一份 Roadmap.md 檔案來規劃開發藍圖。在這份文件中，明確列出接下來要新增的功能、預計優化的項目，以及大致的完成時程，並在每次的開發與重大修改時，回頭檢視，確保前進的方向沒有偏移。 ...

不懂夏威夷？用 Vibe Coding 請 AI 建一個專屬旅遊網

年初做了一個有趣的 Vibe Coding 小專案，起因很蠢——我突然很想去夏威夷，但完全不知道夏威夷有什麼。 因為不瞭解，所以建立了一個網頁去學習 某天看新聞的時候，想到如果今年出國玩也不錯耶。但要去哪裡呢？那就去朝聖某個死神學開直升機的夏威夷。 不過…問題是…我對夏威夷完全不熟，只知道是美國的一部分，但又跟美國本土文化很不一樣。這樣的地方到底有什麼風土民情？到底可以去哪裡觀光？重要的是，要花多少錢呢？ 於是有這些問題，我就用 Vibe Coding 請 Gemini 幫我建立一個網站：2026 夏威夷阿囉哈冒險計畫，來解決我眾多的問題。 一開始我對於夏威夷很不熟悉，因此身為社畜的我，按照基本原則，既然要去，就要去得有意義又省錢，那就去旅遊的時候也參加他們的節日慶典吧！不只逛逛市集，也體驗一下他們的文化。因此我在網站賦予了觀光兼節日的屬性。 接著想到，社畜不能請太多假，會招來白眼，因此要求 AI 幫忙制定一個合理的天數以及旅遊預算，這樣我就可以知道要請多少天的假、準備多少的錢。甚至請 AI 幫我做出省錢計畫，避免我從夏威夷飛回來後要開始吃土。 媲美旅行社的網站與計畫，被現實擊敗 最後完成的 冒險計畫網站，花費我不到半天的時間，就做出可媲美旅行社網站（甚至覺得比很多旅行社厲害），儘管行程和規劃沒有他們那麼專業，但對於完全不知道夏威夷觀光的我，這就是個很好理解及協助規劃的網站。從這邊，我可以快速認識夏威夷一整年著名的節慶與活動，值得探訪的景點，甚至挖出不少原本不會發現的體驗行程。不只讓我對於夏威夷旅遊更嚮往，也使我對於旅行的成本更有概念。最重要的是，不用像以前一樣到處翻旅遊部落格、旅行社行程表，再自己整理成企劃書，全部由 Vibe Coding 就可以做出具有互動性，且資料（還算）齊全的網站，讓資訊收集與行程規劃變得一目了然。 但是計畫來不及變化，今年的我，沒有這麼大筆錢可以飛出去了…Q口Q 不過如果明年有機會，我就可以用 AI 把這個 2026 年計畫改良成更厲害的「2027 年夏威夷計畫」！至於能不能真的飛出去，就不是 Gemini 能解決的問題了。
