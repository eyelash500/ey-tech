## 前言：AI 也有「性格」之分

自從我開始深度使用 AI Agent 進行開發後，我發現不同的大語言模型工具，在處理相同任務時，會展現出截然不同的「性格」。

先前在啟動「類書計畫」時，我嘗試讓 Antigravity 2.0 (Gemini) 協助規劃。結果它在產出：

* PRD
* 系統架構
* 角色權限
* DB Schema
* API 規格

這幾幾份核心文件後，就迫不及待地想直接開工寫程式，完全是個急性子。我得在旁邊不斷地把它拉回來，才沒讓他直接「腦衝」下去。

這個經驗，完全印證了上一篇文章提到的觀點：Antigravity 就像一個「熱血執行者」，而 Claude 則像個「沉穩架構師」。([〈為什麼 AI 總是不聽勸？淺談 Agent 的 Execution Bias (執行偏誤)〉]({{< relref "11506-antigravity-claude.md" >}}))

意識到這點後，我不再把 AI 視為單一的工具，而是開始將它們「擬人化」，想像自己是一個產品經理 (PM)，正在管理一個由不同性格 AI 組成的開發團隊。這篇文章將分享我的「AI 團隊管理」心得，以及我是如何為這些 AI 隊友建立檔案，並指派最適合它們的任務。

## 建立你的 AI 團隊檔案

要管理好團隊，首先要了解每個成員的長處與短處。以下是我為我的 AI Agent 工具建立的團隊檔案：

### 角色 A：熱血執行者 (The Executor)
* **代表模型**：Antigravity Agent
* **性格特質**：行動力極強，對「執行」有著天然的偏好。反應快速，擅長處理具體的、有明確目標的任務。
* **適合任務**：
    * 根據清晰的規格文件寫程式碼
    * 修復一個已知的 Bug
    * 執行重複性的腳本或指令
* **弱點**：缺乏大局觀，在需求不明確時容易「腦衝」，需要人類即時喊停。

### 角色 B：沉穩架構師 (The Planner)
* **代表模型**：Claude
* **性格特質**：深思熟慮，邏輯清晰。擅長處理開放式、需要結構性思考的任務。
* **適合任務**：
    * 將模糊的想法梳理成結構化的 PRD 文
    * 進行程式碼的架構審查 (Code Review)，並提供重構建議
    * 撰寫技術文件，提供更全面的審視與建議
* **弱點**：行動較慢，有時過於謹慎，需要人類推一把才能產出最終結果。

## 我的實戰指令稿 (Playbook)

了解了團隊成員的特性後，我制定了幾個常見場景的協作劇本：

* **場景一：啟動新專案**
    1.  **我 (PM)**：先打開 **Claude (規劃師)**，與它來回討論，把專案的 PRD、API 規格、DB Schema 都確立下來。
    2.  **我 (PM)**：將產出的 Markdown 文件丟進專案資料夾。
    3.  **我 (PM)**：呼叫 **Antigravity (執行者)**，下達指令：「根據 `docs/prd.md` 的內容，開始建置專案。」
    *   *心得：這個階段 Antigravity 的速度優勢很明顯，但產出的程式碼小問題也比較多；如果換成 Claude Code，速度稍慢，但產出品質感覺更穩定。*

* **場景二：緊急 Bug 修復**
    1.  **我 （開發者）**：將終端機的錯誤訊息 (Error Message) 直接複製。
    2.  **我 （開發者）**：貼給 **Antigravity (執行者)**，問：「這個錯怎麼修？」讓它快速提供解法或直接動手修改。
    *   *心得：在修復 Bug 這點上，兩者勢均力敵，都能快速找到問題並修復，甚至會自動找出相關聯的潛在問題一併處理。*

* **場景三：測試與優化**
    1.  **我 （測試者）**：在畫面上進行個人 UAT 測試，檢查功能是否有異常，畫面是否需要調整。
    2.  **我 （開發者）**：將遇到的問題或想優化的項目貼給 **Antigravity (執行者)**，讓它即時處理。
    *   *心得：在一邊測試、一邊快速迭代修正小問題的情境下，Antigravity 的反應速度比 Claude 更勝一籌，是這個階段的最佳隊友。*

## 你的角色是「專案經理」

在 AI 時代，我們的工作並不是被 AI 取代，而是從「動手做」的人，轉變為「下指令」的人。我們需要學習的，是如何「用人唯才」，根據不同 AI 的「性格」與「偏好」，來指派最適合它們的任務。

在 DataCamp 的一篇[比較文章](https://www.datacamp.com/blog/claude-code-vs-antigravity)中，也提到了類似的觀點：Claude Code 是以「Terminal-first」（終端優先）為核心，將人類放在控制鏈的中心；而 Antigravity 則是「Agent-first」（代理優先），自主程度更高。這也解釋了為什麼 Antigravity 反應快速，適合快速驗證，而 Claude Code 則步調沉穩，適合處理複雜任務。

因此，學會管理自己的 AI 開發團隊，是我在 AI 浪潮中找到的核心競爭力。當然只用一套工具打天下也沒問題，但前提是，你必須先摸清它的「性格」，才能真正管理好你的「AI 開發團隊」。
